# 🦊 FoxyProxy

Неофициальный клиент прокси-сети Firefox VPN для Windows 10 и 11. Вход через аккаунт Mozilla, выбор сервера с измерением задержки, локальный SOCKS5 и режим «Весь ПК» в одном приложении.

[Скачать последнюю версию](https://github.com/ShinysLove/FoxyProxy/releases/latest) · [Инструкция для Windows](desktop/README.ru.md) · [Техническая документация исходного клиента на английском](README.en.md)

## Возможности

- Вход на странице Mozilla во встроенном окне WebView2.
- Список серверов Mozilla с измерением TCP-задержки и сортировкой по пингу.
- Локальный SOCKS5 на `127.0.0.1:1080` для отдельных приложений.
- Режим «Весь ПК»: TCP и DNS через виртуальный адаптер sing-box.
- Счётчики полученного, отправленного и общего трафика за подключение.
- Хранение сессии с шифрованием Windows DPAPI и выход из аккаунта.
- Отдельный консольный Go-клиент с HTTP/2, HTTP/3, обновлением токенов и поддержкой systemd на Linux.

Нужен ваш аккаунт Mozilla с доступом к прокси Firefox VPN. Проект не связан с Mozilla официально; работа зависит от доступности сервиса и его интерфейсов.

## Установка и запуск

1. Скачайте `FoxyProxy-Windows.zip` в разделе [релизов](https://github.com/ShinysLove/FoxyProxy/releases/latest) и полностью распакуйте архив.
2. Откройте папку для своей системы и запустите `FoxyProxy.exe`:

   | Папка | Система |
   | :-- | :-- |
   | `Windows-x64` | 64-разрядная Windows, процессоры Intel и AMD |
   | `Windows-x86` | 32-разрядная Windows 10 |
   | `Windows-ARM64` | Windows на процессоре ARM64 |

3. Нажмите «Войти через Firefox» и завершите вход на странице Mozilla.
4. Нажмите «Обновить пинг» и выберите сервер или «Автоматически».
5. Выберите режим и нажмите круглую кнопку питания. Для режима «Весь ПК» подтвердите запрос Windows на права администратора.
6. Нажмите кнопку питания ещё раз или закройте окно, чтобы отключиться.

Тип системы указан в «Параметры → Система → О системе». Среда .NET включена в архив. Если для входа нужен WebView2 Runtime, запустите `MicrosoftEdgeWebview2Setup.exe` из корня распакованного архива при подключённом интернете.

### Режимы подключения

В режиме **«Локальный SOCKS5»** укажите в нужном приложении адрес `127.0.0.1:1080` и тип SOCKS5. Если приложение поддерживает удалённое разрешение DNS через SOCKS5, включите его.

В режиме **«Весь ПК»** TCP и DNS идут через виртуальный адаптер. UDP, кроме DNS, и ICMP блокируются: приложения, которым нужен UDP, могут потерять часть функций. Служебные соединения клиента с Mozilla идут напрямую, чтобы вход и обновление подключения продолжали работать.

Карточка «Трафик за подключение» обновляется каждую секунду. После отключения значения остаются видимыми до следующего подключения или закрытия окна. 1 ГБ равен 1 000 000 000 байт.

## Сборка из исходников

Установите Go 1.25 или новее и .NET SDK 10. Из корня репозитория выполните:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/build-desktop.ps1
```

Скрипт собирает автономные версии x64, x86 и ARM64, загружает sing-box 1.14.4 и установщик WebView2, проверяет SHA-256 sing-box и подпись Microsoft у установщика. Результат — `dist/FoxyProxy-Windows.zip`. Другую папку можно указать параметром `-OutputDirectory`.

## Устройство проекта

Приложение WPF управляет отдельным Go-процессом `foxy-worker`. Он выполняет вход, получает пропуск Guardian, загружает список серверов Mozilla и обслуживает SOCKS5. В режиме «Весь ПК» sing-box передаёт TCP и DNS из виртуального адаптера в локальный SOCKS5. Исходящее соединение с прокси Mozilla использует HTTP/2 CONNECT поверх TLS; консольный клиент также поддерживает HTTP/3 через QUIC.

| Файл или папка | Назначение |
| :-- | :-- |
| `desktop/` | Интерфейс WPF, окно входа WebView2, управление подключением |
| `cmd/proxy-demo/` | SOCKS5, исходящие сессии, обновление пропуска, команды Windows и TUN |
| `fxa.go`, `fxa_browser.go` | Firefox Accounts, OAuth и вход через браузер |
| `fastly.go` | Обработка проверок Fastly перед запросами Firefox Accounts |
| `guardian.go` | Пропуск прокси, активация аккаунта и квота |
| `tokens.go` | Загрузка и сохранение OAuth-токенов CLI |
| `serverlist.go` | Страны, города и серверы из Mozilla Remote Settings |
| `http_client.go` | Общий HTTP-клиент для запросов к API |
| `scripts/build-desktop.ps1` | Сборка Windows-архива |
| `scripts/install-systemd.sh` | Установка службы Linux |

### Авторизация и сессия

В Windows пароль вводится на странице Mozilla в приватном окне WebView2. Сессия хранится в `%LOCALAPPDATA%\FoxyProxy\session.dat` с шифрованием Windows DPAPI. Копии приложения в разных папках используют сессию текущего пользователя. Кнопка «Выйти из аккаунта» удаляет локальную сессию.

В консольном клиенте пароль преобразуется PBKDF2-SHA256 и HKDF в `authPW`, запросы сессии подписываются Hawk. Неподтверждённый вход требует кода из письма или перехода по ссылке. Сессия обменивается на OAuth-токены с областью доступа `profile https://identity.mozilla.com/apps/vpn`. Они сохраняются в `~/.firefox-vpn-tokens.json`; на Unix файл создаётся с правами `0600`. Просроченный access token обновляется через refresh token. Параметр `-login` запускает новый вход.

### Проверки Fastly и доступ Guardian

При HTTP 406 клиент загружает проверку Fastly, обрабатывает задания `pow`, `pat` и `clientmetrics` и сохраняет cookie. Поддерживается до трёх раундов ответа и до пяти повторов запроса FxA. Cookie привязан к внешнему IP; при повторяющихся сбоях из-за смены IP параметр `-api-proxy` позволяет использовать постоянный выход для API.

| Метод и путь Guardian | Назначение |
| :-- | :-- |
| `GET /api/v1/fpn/token` | Получить JWT-пропуск и заголовки квоты |
| `GET /api/v1/fpn/status` | Проверить право аккаунта на доступ |
| `POST /api/v1/fpn/activate` | Активировать доступ к прокси |

HTTP 429 означает исчерпание квоты. При HTTP 401/403 клиент пытается обновить OAuth-токен и активировать аккаунт. Параметр `-guardian` принимает только абсолютный HTTPS-адрес: запросы содержат токен аккаунта. Временные метки JWT проверяются относительно локальных часов, предусмотрена коррекция смещения.

### Серверы, квота и соединения

Список серверов берётся из коллекции `vpn-serverlist` Mozilla Remote Settings. Используются узлы с протоколом `connect`, не находящиеся в карантине. В CLI задайте код или название страны через `-country` либо конкретный сервер через `-proxy`. При нескольких доступных странах выбор должен быть явным; единственная страна выбирается автоматически.

`-proxy-state-file` сохраняет hostname и метаданные узла для следующего запуска. Выбор сбрасывается после трёх последовательных ошибок запуска. Сохранение hostname не гарантирует неизменность физического сервера, маршрута или внешнего IP. `-verify-exit` проверяет фактические IP и страну через туннель; ошибка проверки не останавливает подключение.

`-session-token` принимает токен или `.txt` с одним токеном на строку. Пустые строки, комментарии `#` и дубликаты пропускаются. Квота проверяется каждые 15 минут. При её исчерпании или окончательном отклонении токена клиент переключается на следующий. Состояние хранится в `<файл-токенов>.state` и связано с SHA-256 списка. Изменение файла начинает перебор заново. Если токены закончились, клиент завершает работу.

Пропуск обновляется за две минуты до истечения срока, по возможности внутри текущей сессии. Подтверждённо сломанная сессия пересоздаётся; учитываются ошибки нескольких разных целей, чтобы сбой одного сайта не вызывал смену выхода. Зависшее обновление завершается выходом процесса для перезапуска службой.

`-upstream-conns` создаёт несколько исходящих сессий с привязкой клиента по IP. Для одного пользователя или sing-box обычно достаточно `1`; увеличение числа сессий само по себе не повышает пропускную способность.

## Консольный клиент

```bash
go build -o fox-proxy ./cmd/proxy-demo
./fox-proxy -login -print-info
./fox-proxy -country US -listen 127.0.0.1:1080
```

При входе укажите почту и пароль, затем подтвердите вход, если этого требует Mozilla. `-print-info` выводит сведения об аккаунте, квоте и серверах. В Windows назовите файл `fox-proxy.exe` и запускайте через `./fox-proxy.exe`.

### Параметры CLI

| Параметр | По умолчанию | Назначение |
| :-- | :-- | :-- |
| `-country` | пусто | Код или название страны |
| `-proxy` | пусто | URL прокси или `host:port`; несовместим с `-country` |
| `-listen` | `127.0.0.1:1080` | Адрес локального SOCKS5 |
| `-login` | `false` | Принудительный новый вход |
| `-print-info` | `false` | Вывести аккаунт, квоту и серверы, затем завершиться |
| `-session-token` | пусто | Токен или путь к файлу пула |
| `-api-proxy` | пусто | HTTP, HTTPS или SOCKS5 для запросов к API |
| `-fxa-user-agent` | пусто | Заменить закреплённый Firefox User-Agent для FxA |
| `-guardian` | `https://vpn.mozilla.org` | HTTPS-адрес Guardian |
| `-timeout` | `20s` | Тайм-аут исходящего подключения |
| `-handshake-timeout` | `10s` | Тайм-аут рукопожатия SOCKS5; `0` без ограничения |

| `-max-conns` | `256` | Максимум одновременных клиентов; `0` без ограничения |
| `-upstream-conns` | `1` | Число исходящих сессий |
| `-h3` | `false` | HTTP/3 вместо HTTP/2 |
| `-verify-exit` | `true` | Проверить фактический внешний выход |
| `-exit-check-url` | `https://www.cloudflare.com/cdn-cgi/trace` | HTTPS-адрес проверки выхода |
| `-exit-check-timeout` | `10s` | Тайм-аут проверки выхода |
| `-proxy-state-file` | пусто | Файл сохранённого выбора сервера |
| `-status-file` | пусто | Файл JSON со статусом работы |
| `-verbose` | `false` | Подробные журналы, включая посещаемые узлы |

## Служба systemd на Linux

```bash
sudo COUNTRY=US LISTEN=127.0.0.1:1088 ./scripts/install-systemd.sh install-login
```

Скрипт собирает `/usr/local/bin/firefox-vpn-proxy`, создаёт пользователя `firefox-vpn`, каталог состояния `/var/lib/firefox-vpn-client`, настройки `/etc/default/firefox-vpn-client`, службу и таймер проверки. Вход выполняется от служебного пользователя. Служба стартует при наличии токенов и выбранной страны, сервера или сохранённого выбора.

| Команда скрипта | Действие |
| :-- | :-- |
| `install` | Собрать, установить и запустить при наличии настроек и токенов |
| `login` | Выполнить вход от пользователя службы и запустить её |
| `install-login` | Установить без запуска, затем выполнить вход |
| `health` | Проверить работоспособность вручную |
| `status` | Состояние службы и таймера |
| `restart` | Перезапустить службу и таймер |
| `uninstall` | Удалить службу, бинарный файл и настройки; `PURGE=1` удаляет также состояние и пользователя |

Таймер проверяет активность службы, срок действия пропуска и CONNECT до контрольных узлов. После нескольких последовательных неудач всех целей служба перезапускается. Намеренно остановленная служба не запускается. Без Python проверяется только локальный TCP-порт.

Служба использует отдельного пользователя без интерактивного входа, `NoNewPrivileges`, `PrivateTmp`, `ProtectSystem=full`, `ProtectHome` и ограничение семейств адресов. `Restart=always` перезапускает процесс через 10 секунд после сбоя.

Измените `/etc/default/firefox-vpn-client`, затем выполните `systemctl restart firefox-vpn-client.service`.

| `IDLE_TIMEOUT` | `0` | Тайм-аут простоя |
| `MAX_CONNS` | `256` | Максимум клиентов |
| `UPSTREAM_CONNS` | `1` | Число исходящих сессий |
| `USE_H3` | `0` | Использовать HTTP/3 |
| `VERIFY_EXIT` | `1` | Проверять выход |
| `EXIT_CHECK_URL` | `https://www.cloudflare.com/cdn-cgi/trace` | Адрес проверки выхода |
| `EXIT_CHECK_TIMEOUT` | `10s` | Тайм-аут проверки выхода |
| `VERBOSE` | `0` | Подробные журналы |

| `HEALTH_INTERVAL` | `30s` | Интервал проверки |
| `HEALTH_TIMEOUT` | `5` | Тайм-аут одной проверки, секунды |
| `HEALTH_VERBOSE` | `0` | Записывать успешные проверки |
| `HEALTH_TARGET` | пусто | Старый вариант с одной целью |
| `HEALTH_TARGETS` | `www.google.com:443,example.com:443` | Цели CONNECT через запятую |

Переменные команды установки переопределяют файл настроек для этого запуска. Повторная установка сохраняет токены и конфигурацию. Для множества клиентов можно начать с `MAX_CONNS=1024`, `UPSTREAM_CONNS=1`, `IDLE_TIMEOUT=5m`. Для длительных SSH- и WebSocket-соединений оставьте `IDLE_TIMEOUT=0`. Число клиентов должно быть ниже лимита файловых дескрипторов; служба задаёт `LimitNOFILE=65535`.

## Безопасность и ограничения

- SOCKS5 слушает `127.0.0.1` без аутентификации. Не открывайте его в публичную сеть.
- Windows-сессия защищена DPAPI. Токены CLI и файл пула являются учётными данными: ограничивайте доступ и не публикуйте их.
- Windows-приложение использует страницу входа Mozilla, CLI передаёт производное значение `authPW`.
- По умолчанию цели CONNECT скрыты в журналах. Параметр `-verbose` раскрывает посещаемые узлы.
- Выбранная страна и фактический выход могут различаться; клиент показывает их отдельно.
- Используйте собственный аккаунт с доступом к сервису. Изменения Mozilla могут потребовать обновления клиента.

## Решение проблем

| Симптом | Что проверить |
| :-- | :-- |
| Не открывается окно входа | Установите WebView2 Runtime из архива |
| Не включается «Весь ПК» | Подтвердите права администратора и полностью распакуйте архив |
| `multiple VPN countries are available` | Укажите `-country` или `-proxy` |
| `guardian returned HTTP 403` | Проверьте доступ аккаунта к VPN; клиент пробует обновление токена и активацию |
| Ошибки Fastly или HTTP 406 | Повторите вход; при смене IP используйте `-api-proxy` с постоянным выходом |
| `no session tokens left in the pool` | Дождитесь обновления квоты или добавьте действующие токены |
| `no refresh token available for background renewal` | Войдите от того же пользователя; для systemd используйте команду `login` скрипта |
| Страна `unknown` | Узел `-proxy` может отсутствовать в списке Mozilla |
| `exit verification failed` | Проверьте адрес теста; ошибка не останавливает прокси |
| Служба сразу перезапускается | Проверьте `journalctl -u firefox-vpn-client.service -n 100`, токены, настройки и занятость порта |

Журналы CLI выводятся в stderr с временем RFC3339 и уровнем сообщения. Дополнительные заметки по эксплуатации исходного клиента находятся в [OPERATOR.md](OPERATOR.md).
